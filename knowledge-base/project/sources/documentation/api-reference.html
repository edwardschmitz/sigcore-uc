.NET API Reference

Use the SigCoreCommon.SigCoreSystem class to communicate with a SigCore UC controller from C# applications.

C# / .NETSource: SigCoreSystem.csDeveloper reference

Overview

SigCoreSystem is the primary application-facing class for connecting to a controller, reading digital and analog inputs, operating outputs, working with PID controllers, and reading or updating configuration. Its asynchronous methods return Task or Task<T>.

The examples below use the SigCoreCommon namespace and a reference to the SigCoreCommon library. Most value-reading methods are request/response operations. Output and configuration setters generally send commands without an applied-state acknowledgment, so read the state back when confirmation matters.

Channel numbering: the Control Panel uses zero-based API channel indices. For example, physical relay R1 is channel 0.

Device address: use the hostname when available, such as SCUC-000019.local, with a reachable IP address as a fallback. The default Core TCP port is 7020.

Getting started

Create a SigCoreSystem, attach event handlers, and call StartAsync(). Use Stop() or dispose the object to end the session.

using System;
using System.Threading.Tasks;
using SigCoreCommon;

class Program
{
    static async Task Main()
    {
        using var device = new SigCoreSystem();
        device.ConnectionStateChanged += state =>
            Console.WriteLine($"Connection: {state}");
        device.DigitalInChanged += values =>
            Console.WriteLine($"DI1: {values[0]}");

        await device.StartAsync("SCUC-000019.local");
        bool input = await device.GetDInAsync(0);
        Console.WriteLine($"DI1 is {input}");

        // Example only: command relay R1 if it is safe to do so.
        // await device.SetRelayAsync(0, true);

        device.Stop();
    }
}

StartAsync() completes after an initial successful connection, handshake, and subscription send. It automatically attempts to reconnect after a lost managed connection. For UI programs, event callbacks may arrive on a non-UI thread, so marshal UI updates to the correct thread.

This sample is based on the public method signatures. It has not been compiled or tested against a connected device as part of this documentation pass.

Device discovery

SigCoreDiscovery discovers available SigCore UC controllers using mDNS service _sigcore._tcp.local., avoiding the need to enter a hostname or IP address. The discovery implementation checks that Core accepts a TCP connection on port 7020 and returns only reachable devices.

DiscoverAsync

public Task<IReadOnlyList<SigCoreDevice>> DiscoverAsync()

Instantiate SigCoreDiscovery and await DiscoverAsync(). An empty collection means no reachable controllers were found during that scan.

using SigCoreCommon;

var discovery = new SigCoreDiscovery();
IReadOnlyList<SigCoreDevice> devices = await discovery.DiscoverAsync();

foreach (var device in devices)
{
    Console.WriteLine($"{device.Name} | {device.Address} | {device.Version}");
}

Select and connect to a controller

When one device is discovered, an application can select it automatically. When multiple devices are discovered, let the operator choose the intended controller before operating I/O.

using SigCoreCommon;

var discovery = new SigCoreDiscovery();
var devices = await discovery.DiscoverAsync();

if (devices.Count == 0)
{
    Console.WriteLine("No reachable SigCore UC devices found.");
    return;
}

int selectedIndex = 0;
if (devices.Count > 1)
{
    for (int i = 0; i < devices.Count; i++)
        Console.WriteLine($"{i + 1}. {devices[i].Name} ({devices[i].Address})");

    Console.Write("Select device number: ");
    if (!int.TryParse(Console.ReadLine(), out int choice) ||
        choice < 1 || choice > devices.Count)
    {
        Console.WriteLine("Invalid selection.");
        return;
    }

    selectedIndex = choice - 1;
}

var selected = devices[selectedIndex];
using var system = new SigCoreSystem();
try
{
    await system.StartAsync(selected.Address!);
    Console.WriteLine($"Connected to {selected.Name}");
    Console.WriteLine($"DI1: {await system.GetDInAsync(0)}");
}
finally
{
    system.Stop();
}

How discovery works

  1. Query mDNS for _sigcore._tcp.local..
  2. Collect advertised addresses and retain IPv4 candidates.
  3. Try ordinary IPv4 addresses before 169.254.x.x link-local addresses.
  4. Attempt a TCP connection to port 7020, with a one-second timeout per candidate.
  5. Return devices for which at least one address accepts a connection.

Discovery success indicates that a TCP connection was accepted at scan time. It does not guarantee a later application connection will succeed. The current implementation does not return devices that advertise themselves but fail the TCP check.

Requirements and troubleshooting

The controller and computer need network connectivity, the network must allow mDNS discovery traffic, and Core must accept TCP connections on port 7020. Discovery currently selects IPv4 only; multicast discovery may not traverse subnet boundaries without network support.

If discovery returns no devices, verify power, network access, the Core service, and multicast permissions. If you know the IP address, you can connect directly with StartAsync("192.168.1.100"), using the controller's actual address.

SigCoreDiscovery is part of SigCoreCommon and uses Zeroconf internally. Deploy the dependencies required by that assembly with your application.

Connection

For applications that keep a device connection open, prefer managed StartAsync() and monitor ConnectionStateChanged.

Subscriptions

Managed connections created with StartAsync() subscribe automatically. Subscribe explicitly only when using the one-shot connection API.

SubscribeAsync

public Task SubscribeAsync()

Requests the initial state snapshot and subsequent change alerts. Completion means the subscribe message was sent, not that the snapshot arrived.

Validation notes

This reference documents the application-facing members of SigCoreSystem. Public message-dispatch handlers and transport callbacks are implementation-facing and are intentionally excluded from the application method catalog.

Before publication, compile the sample against the distributed SigCoreCommon library and confirm channel limits, payload member validation, server-side commander permissions, and the device response to rejected commands. These details cannot be fully validated from the interface file alone.

Factory reset behavior: although an older source comment calls it fire-and-forget, the present implementation waits for a result, with a 30-second timeout.
